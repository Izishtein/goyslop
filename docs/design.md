# Design & UX

## Решено (2026-08-04)

| Вопрос | Решение |
|--------|---------|
| Общая концепция | **Современный clean UI** — карточки, воздух, прогресс-бары HP/MP, аккуратная типографика (не имитация бумажного бланка) |
| Структура страницы | Один длинный скролл на печати, **CSS-раскладка в 2-3 колонки на широком экране** (с 2026-09-25, см. ниже) — порядок секций в DOM не менялся ни разу |
| Целевое устройство | **Десктоп в первую очередь, но responsive** — на планшете/телефоне не разваливается |
| Тема | Светлая + тёмная. По умолчанию следует системной (`prefers-color-scheme`); с 2026-09-13 есть ручной переключатель «Системная/Светлая/Тёмная» рядом с выбором языка, переопределяет системную. `color-scheme` для нативных контролов следует эффективной теме |
| Термины в RU-локали | **Русский + английский в скобках**: «Точность (Accuracy)». Понятно новичку и сверяется с англоязычными PDF, по которым играют |
| Таблица характеристик | **Карточки** (3×2 на десктопе): крупный Total + модификатор, под ними компактная разбивка Base/Корр./Прирост/Предм. |
| HP/MP | **Прогресс-бары**. Цвет HP отражает опасность: >50% зелёный, 25–50% янтарный, <25% красный |
| Классы и уровни | **Бейджи-пилюли**, не список строк |
| Снаряжение | **Таблицы** (данные по своей природе табличные), в обёртке с горизонтальным скроллом на узких экранах |
| Inline editing | Всё редактируется на месте, без режимов «просмотр»/«редактирование» |

## Реализация

- Токены дизайна — `src/index.css` (`--surface`, `--text-muted`, `--accent`, шкала `--sp-*`, радиусы, тени). Обе темы задаются там же
- Компонентные стили — CSS Modules рядом с компонентами
- Печать — `src/print.css` (страница, палитра, скрытие органов управления, таблицы) + `@media print` внутри CSS-модулей для того, что зависит от локальных классов (карточки → плоские блоки)

## Осознанно не сделано

- **Radix UI не задействован.** Пакет в зависимостях, но ни один примитив не понадобился: весь UI — нативные контролы, они доступны и печатаются без доработок. Пригодится, когда появятся диалоги/поповеры/комбобоксы
- **Иконок и арта нет** — ни иконок типов снаряжения/школ магии, ни аватара персонажа. Вопрос лицензионно чистых наборов (Lucide, Phosphor, game-icons.net) не поднимался
- Боковая навигация по секциям — не делалась, компактность решена CSS-раскладкой вместо неё (см. ниже)

Базовая доступность была заложена с начала (не пункт этого списка, а фон для аудита ниже): явные `htmlFor`/`id` у всех полей, `aria-label` у значений и табличных инпутов, видимый фокус (`:focus-visible`).

## Переключатель темы (2026-09-13)

Раньше тема только следовала системной — владелец попросил добавить ручной переключатель. Реализовано как третье состояние поверх существующего механизма, не замена ему:

- `state/theme.ts` — `themeAtom` (`'system' | 'light' | 'dark'`, `atomWithStorage('sw25.theme', 'system')`, как и `charactersAtom`/`activeCharacterIdAtom`).
- `App.tsx` — select рядом с переключателем языка; на изменение атома ставит/снимает `data-theme` на `<html>`.
- `index.css` — `@media (prefers-color-scheme: dark)` теперь работает через `:root:not([data-theme="light"])`, плюс отдельный блок `:root[data-theme="dark"]` с теми же значениями токенов вне медиа-запроса. Так explicit-выбор побеждает системную тему в обе стороны при одинаковой специфичности (`[data-theme=...]` — атрибутный селектор, специфичнее голого `:root`). `color-scheme` тоже переопределяется под явный выбор, иначе нативные контролы (скроллбары, датапикеры) остаются в системной теме независимо от токенов.
- `index.html` — маленький синхронный inline-скрипт в `<head>`, читает `sw25.theme` из localStorage и сразу проставляет `data-theme` до того, как загрузится React/jotai — иначе при выборе темы, противоположной системной, при каждой перезагрузке был бы короткий блик неправильной темой.
- Печать: переключатель лежит в той же обёртке `.langSwitch`, что и языковой — уже скрывается в `@media print` тем же правилом, отдельного не заводилось.

Проверено в браузере (Playwright/Chrome, `emulateMedia({ colorScheme })` для обоих системных состояний): «Тёмная» поверх светлой системной, «Светлая» поверх тёмной системной, «Системная» в обе стороны корректно возвращает поведение к `prefers-color-scheme`, `data-theme` выставлен уже к моменту первой отрисовки после перезагрузки (блика нет), консоль пустая. Тесты — `App.test.tsx` (`describe('theme switch')`): дефолт `system` без атрибута, переключение на `dark`/`light` ставит атрибут, обратно на `system` снимает.

## WCAG-аудит контраста (2026-09-13)

Посчитаны коэффициенты контраста (WCAG 2 relative luminance) для всех пар «текст/фон» и «UI-элемент/фон» из токенов `src/index.css`, в обеих темах.

**`--warn` исправлен:** амбер — цвет предупреждения о недопустимой Коррекции характеристики в форме создания и средней полосы HP-бара — в светлой теме давал только 2.95:1 на белом, ниже порога 4.5:1 для текста и 3:1 для non-text UI (заливка прогресс-бара). Затемнён до `#98680e` (4.5–4.6:1 и на `--surface`, и на `--bg`), проверено в браузере: предупреждение читается чётко, не уходит в грязно-коричневый, отличимо от `--danger`. Тёмная тема `--warn` контраст уже держала (8.19:1) и не менялась.

**`--text-faint` исправлен:** самый светлый из трёх текстовых токенов (ярлыки полей, диапазоны костей, пометки источника, «не изучено» и т.п.) в светлой теме давал 2.78:1 на `--bg` / 3.00:1 на `--surface`, в тёмной — 3.43–3.76:1 — везде ниже 4.5:1 для обычного текста (весь этот текст мелкий, 0.68–0.85rem, порог «крупного текста» 3:1 не применяется). Владельцу показаны скриншоты текущего и AA-варианта бок о бок (форма создания персонажа, обе темы) — выбран AA-вариант: `#6f6f7c` в светлой теме (4.5–4.6:1), `#828291` в тёмной (4.5–4.6:1). Внешне стал чуть темнее/светлее и заметно легче читается, но всё ещё яснее различим от `--text-muted`, чем от `--text` — трёхуровневая иерархия текста сохранена, просто с меньшим разрывом между вторым и третьим уровнем.

**Найдено, не критично:** `--border`/`--border-strong` как граница инпутов/селектов на `--surface` — 1.29:1/1.58:1 в светлой теме, ниже рекомендованных 3:1 для границ значимых UI-компонентов (WCAG 1.4.11). Общепринятая практика минималистичных UI (в т.ч. у большинства популярных дизайн-систем) сознательно ниже этого порога; не трогалось.

## Компактная раскладка листа (2026-09-25)

§ 5.5 roadmap.md закрыт способом, который сам roadmap уже намечал: «чисто CSS-раскладка (grid/flex-колонки на экране, с откатом на одну колонку в `@media print`), не трогая порядок секций в DOM».

`.sheet` (`CharacterSheetView.module.css`) переведён с `display: flex; flex-direction: column` на обычный block-flow + `margin-bottom` на прямых детях (multi-column layout игнорирует flex-контейнеры, а `gap` для block-контейнеров ещё не везде надёжен) и получил CSS multi-column: `column-count: 2` от 1024px, `column-count: 3` от 1600px, `column-gap`, `break-inside: avoid` на каждой карточке, чтобы ни одна секция не резалась пополам между колонками. `column-fill` не трогался — браузерный дефолт `balance` сам уравнивает высоту колонок. Шапка (`.identity`) и полоса HP/MP/спасбросков (`.vitals`) получили `column-span: all`, чтобы остаться на всю ширину над колонками. На печати `column-count: 1` и `margin-bottom` вместо колоночного `gap` — макет возвращается к прежнему одноколоночному виду построчно, `column-span` сброшен в `none`. DOM-порядок секций не менялся ни разу — правки только в CSS-модуле, ни один компонент секции не тронут.

Проверено в браузере (Playwright, `channel: 'msedge'`): 1440px — 2 колонки, 1800px — 3 колонки, 420px (мобильный) — по-прежнему одна колонка (брейкпоинт 1024px не сработал), печатный превью (`emulateMedia('print')`) — снова одна колонка сверху вниз, как до этой правки.

**Уточнение в тот же день, по скриншоту владельца.** Одинаковая ширина колонки не подходит секциям с по-настоящему широкими таблицами — Снаряжение (12 колонок в таблице оружия), Техники/Песни (9 колонок у Spellsongs), Маунты (13 колонок в посекционной таблице характеристик мунта) — в трети экрана заголовки переносились на две строки и таблица уходила в горизонтальный скролл. Владелец сослался на стороннее приложение как пример, где такие таблицы занимают всю доступную ширину, а не одну колонку сетки.

Решено модификатором `.sectionWide` (`column-span: all` внутри того же `@media (min-width: 1024px)` блока) — точечно на `EquipmentSection`, `ArtsSection`, `MountsSection` (`className={`${styles.section} ${styles.sectionWide}`}`), остальные 14 секций остались в обычном потоке колонок. Разбор по каждой секции — количество `<th>` в единственной самой широкой таблице раздела (`grep -c '<th' *.tsx`, не общая сумма по файлу, где несколько мелких таблиц могли завысить счёт): Snaryazhenie/Arts/Mounts вышли далеко за 8 колонок, остальные (Spells 5, Evocations 6-7, Tactician 4, Classes 5, CombatStats — три мелких таблицы по 2-4 каждая) остались в пределах, комфортных для трети экрана. Печать не тронута — уже существующий сброс `.sheet > * { column-span: none }` в `@media print` покрывает и новый класс.

Проверено в браузере (Playwright, `channel: 'msedge'`, тот же пример персонажа) на 1440px и 1900px — Снаряжение растягивается на всю ширину и над, и под ним остальные секции продолжают течь по 2-3 колонкам как раньше, консоль пустая.

**Второе уточнение в тот же день: пустые поля по бокам на Full HD.** Многоколоночная раскладка выше срабатывает по ширине *вьюпорта* (`@media (min-width: 1024px/1600px)`), но сам контейнер `.app` (`App.module.css`) держал `max-width: 1000px` безусловно — колонки укладывались внутри этой фиксированной коробки, а не в доступную ширину экрана, поэтому на 1920px оставались огромные пустые поля по бокам при всё ещё тесных колонках. `.app` получил те же два брейкпоинта, что и `.sheet`: `max-width: 1400px` от 1024px, `1800px` от 1600px — контейнер и раскладка теперь растут согласованно. Мобильный сценарий (`max-width: 640px`) и печать (`max-width: none`) не тронуты. Проверено на 1920×1080 (3 колонки, разумные поля ~60px) и 1366×900 (2 колонки, без лишнего воздуха).

## Плотность и читаемость: слитая шапка + сворачиваемые секции (2026-09-25)

Владелец, тем же заходом, что и ширина на Full HD, попросил в целом улучшить плотность и читаемость: некоторые секции слишком объёмные (в первую очередь — карточка персонажа сверху, куда можно перенести HP/MP-бар в уменьшенном виде), а часть секций «можно соединить с возможностью переключения». Спросили, что именно волнует больше всего (AskUserQuestion, множественный выбор) — выбраны сразу два пункта: плотность/читаемость таблиц и форм, и объединение/сворачивание объёмных секций.

**Шапка + HP/MP слиты в одну карточку.** `.identity` (шапка: портрет, имя, раса/класс) и `.vitals` (HP/MP-бары, Стойкость/Воля) раньше были двумя отдельными полноширинными карточками подряд — вместе самое высокое и наименее информационно плотное место на листе. Теперь одна карточка: `.identityTop` несёт прежнюю раскладку шапки, `.vitals` — вторая строка той же карточки (не своя, а общая рамка/тень/padding), с тонкой верхней границей-разделителем вместо отдельной карточки. Заодно сам HP/MP-бар уменьшен, как и просил владелец: высота полосы 8px → 6px, `gaugeValue`-инпут уже (4.5em → 3.6em), `statValue` (Стойкость/Воля) 1.35rem → 1.1rem, шаг сетки `.vitals` 240px → 190px. В многоколоночной раскладке `column-span: all` теперь висит только на `.identity` (вложенный `.vitals` этого не требует).

**Девять «опциональных» секций → пять уже прятались сами, ещё три стали сворачиваемыми.** Аудит показал: `ArtsSection`/`EvocationsSection`/`MountsSection`/`GeomancerSection`/`TacticianSection`/`EssenceWeavingSection` уже возвращают `null` целиком, когда у персонажа нет ни нужного класса, ни единой записи — этот паттерн существовал и раньше, просто не был замечен как решение проблемы объёма. Из девяти «специфичных» секций только три реально всегда рендерили полную пустую карточку: `SpellsSection` (заклинания не привязаны к одному классу так жёстко, и есть тестируемое поведение — сообщение «не колдует» должно оставаться на месте, не исчезать вместе с секцией, см. `SpellsSection.test.tsx`), `SchoolsSection` и `WorkSkillsSection` (оба открыты любому классу через Reputation — им, в отличие от Mounts/Geomancer/Tactician/EssenceWeaving, некуда «вернуться», если спрятать целиком: нет второго места на листе, которое заново их покажет).

Эти три переведены с `<section>`/`<div className={styles.sectionHead}>` на `<details data-collapsible>`/`<summary className={styles.sectionHead}>` — нативный disclosure-виджет вместо самодельного, свёрнут по умолчанию, если у секции нет ни подходящего класса, ни уже внесённых записей (для Spells — есть волшебный класс или есть хоть одно заклинание; Schools/WorkSkills — только «уже есть записи», без классового гейта). `open` передаётся только как начальное значение (не управляется React дальше) — ручной клик по `<summary>` держится весь сеанс, ничего не перезаписывает его обратно.

**Печать: `<details>` не имеет права прятать что-либо на бумаге.** Печатный лист по замыслу показывает все секции целиком, даже пустые — это лист, который потом дозаполняют от руки, тот же принцип, что уже действует для остальных секций. UA-стиль браузера прячет содержимое закрытого `<details>` через `display:none`, и это нельзя надёжно перебить чистым CSS без риска задеть другие приёмы печати (`.subsection {display:contents}` уже используется для похожей цели). Решение — не CSS, а JS: `CharacterSheetView.tsx` слушает `window.beforeprint`/`afterprint`, перед печатью принудительно выставляет `open=true` каждому `<details data-collapsible>` (запомнив прежнее состояние в `dataset.wasOpen`), после печати возвращает как было. Работает и для кнопки «Печать / Сохранить в PDF» (`window.print()`), и для Ctrl+P напрямую — оба реально проходят через `beforeprint`/`afterprint`, а не только через саму кнопку.

Проверки: новые тесты в `SpellsSection.test.tsx`/`SchoolsSection.test.tsx`/`WorkSkillsSection.test.tsx` (свёрнуто/раскрыто по умолчанию через DOM-атрибут `open`, не через видимость — jsdom не считает layout, так что видимость нельзя было бы проверить достоверно) и новый тест в `CharacterSheetView.test.tsx` (`fireEvent(window, new Event('beforeprint'))` действительно раскрывает все `[data-collapsible]`, `afterprint` возвращает как было). Браузерная проверка (Playwright, `channel: 'msedge'`) — Fighter без магии: «Заклинания»/«Школы»/«Work Skills» свёрнуты, клик по «Школы» разворачивает; Sorcerer: «Заклинания» открыты сразу; печатный превью с искусственно продиспатченным `beforeprint`-событием показывает все три секции развёрнутыми полностью, включая пустые «Заклинания ещё не записаны», консоль пустая.
