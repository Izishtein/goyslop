## A. Брать сразу (дёшево, большая отдача)

**A1. Оракул читает журнал.** Mythic держит два списка по 25 строк, разбитые на секции по 5; бросок «секция → строка», пустая строка = «выбери или перебрось». Самое важное в идее: **записи добавляются повторно, если участвовали в сцене (вес, не более 3)**, и тогда чаще всплывают. Наш журнал уже хранит `npc`, `threat`, `thread` с флагом `closed`. План:
- в `CampaignEntry` добавить `weight` (1–3, `.default(1)`);
- события оракула получают фокусы «действие NPC», «NPC плохо/хорошо», «ближе к нити», «дальше от нити», «закрыть нить» и **берут запись из журнала взвешенным броском**; пустой список → фокус «текущая ситуация» (правило книги);
- фокусы «удалённое событие», «неясное событие», «новый NPC», «PC плохо/хорошо», «текущая ситуация» остаются как есть. Таблицу диапазонов d100 пишем свою;
- кнопка «Добавить ещё раз» (вес +1) у записи, участвовавшей в сцене; правило «не более трёх».
- Бонус: в списки можно класть **места, группы и предметы** — у нас это фракции гекс-карты и группы подземелья. Автозаполнение журнала из карты («поселение», «фракция N», «логово») даёт событиям сразу SW2.5-окраску.

**A2. Мастер конца сцены.** По кнопке «Закончить сцену»: (1) «PC контролировали сцену?» → хаос −1 / +1; (2) предложить добавить участвовавших NPC и нити (или поднять их вес); (3) убрать неактуальное. Режимы хаоса из книги: обычный, «возврат к среднему» (после успеха хаос растёт, после провала падает — меньше крайностей) и «случайный» (d10 ≤ хаос → −1, иначе +1, не требует оценки сцены).

**A3. Изменённая сцена.** Генератор правки ожидаемой сцены: d10 → убрать/добавить персонажа, ослабить/усилить действие, убрать/добавить предмет, 7–10 — две правки (повтор 7–10 перебрасывается, противоречащую правку игнорировать, невозможную перебросить). Стратегии книги: «следующее по ожиданиям», «одна поправка», вопрос судьбе, слова из Meaning. Кнопки в панели сцены.

**A4. Автоматический Interrupt и выбор фокуса.** Если игрок застрял — сцена сразу «прерванная», без проверки хаоса. Можно **выбрать** фокус вместо броска: рекомендация книги — раз в пять сцен («Choosing the Event Focus»); «ближе к нити» вытаскивает игру из тупика.

**A5. Приёмы толкования (в подсказках интерфейса, без механики).** «Правило „не знаю“» (не получается истолковать — отбрось событие и играй дальше), «не более двух вопросов на деталь», «углубление смысла» (ещё один бросок слов, можно из другой таблицы), **соединители слов** (of / and / but / -ly между двумя словами, если пара не говорит ничего), толкование ответов: Да = ожидание, Нет = *следующее по вероятности* (а не обязательно «наоборот»), Исключительное Да = усиление, Исключительное Нет = обратное или усиленное «следующее». Вопросы стоит ставить на *напряжение*, а не на то, что «убьёт» сюжет.

**A6. Режим «оракул как правило».** Если надо заменить недостающее правило SW2.5 ответом оракула: считать хаос = 5, исключительные результаты — обычными (если у правила нет степеней успеха), случайные события — игнорировать. Один флажок в панели вопроса; обратный случай — «нарративный» вопрос с обычным хаосом.

## B. Следующие фазы (средний объём)

**B1. Прогресс нити (Thread Progress Track).** У нити в журнале — трек 10 / 15 / 20 очков. «Прогресс» (+2): значимый шаг к цели; «Flashpoint» (+2): драматичный эпизод с нитью; если за фазу в 5 очков flashpoint не было — он происходит (событие с фокусом «текущая ситуация»). **Plot Armor:** нить нельзя закрыть до Conclusion, ни обычной игрой, ни событием «закрыть нить». Conclusion — драматичная сцена без брони (нить закрывается *не обязательно*); при переполнении её можно отложить на следующую сцену без проверки хаоса. **Discovery Check:** когда игрок застрял, вопрос «что-то обнаружено?» с шансом не ниже 50/50; при «Да» — d10 + очки трека по таблице (прогресс +2/+3, flashpoint +2/+3, трек +1/+2, усиление уже сделанного +1/+2); Исключительное Нет — до конца сцены искать нельзя. Совет «дробить нити» (три формулировки одной цели дают событиям более точный контекст). Привязка к SW2.5: закрытие главной нити ≈ «сессия» для опыта (книга предлагает именно это: сессия соло = достижение значимой цели).

**B2. Ключевые сцены (Keyed Scenes).** Правило «если X, то в следующей сцене Y»: триггеры-счётчики («3 сцены без боя»), случайные («1–3 на d10»), рубежи («после 15-й сцены бой с боссом при 1–3»), события для темы приключения (бродячий монстр, ловушка, головоломка, ужас). Каждая запись: событие, триггер, счётчик, разово/повторно, «обнуление» (если нужное уже случилось само). Отсюда естественно растут **наши готовые таблицы**: бродячий монстр уже есть на гекс-карте — ключевая сцена «каждые N сцен встреча по биому»; «тон подземелья» (по 1–2 на d10 за сцену — встреча, 1 — ловушка, 1 — головоломка) совпадает с генератором подземелья. Проверка триггера может быть «отложенной» (бросать уже в начале сцены).

**B3. Вкус хаоса.** Три облегчённых таблицы (средний, низкий, без хаоса): хаос меняет шанс слабее или совсем не меняет. «Без хаоса» нужен A6.

**B4. Очки опасности (Peril Points).** Запас (по умолчанию 2) «спасений»: потратить, чтобы изменить повествование и не дать приключению оборваться; пополнение — по желанию (каждая сессия или фиксированный запас). Для нас — счётчик на экране «Соло»; полезно рядом с Death Check (CR I с. 110, 184), но *не вместо* него.

**B5. Готовые приключения (сценарии из `E:\НРИ`).** Книга советует: хаос и Fate Questions остаются, **Altered/Interrupt не используются** — проверка ожидаемой сцены лишь вызывает дополнительное случайное событие; отдельный список **Adventure Features** (бродячие монстры, видения, особые механики приключения) и укороченная таблица фокусов (особенность приключения, действие NPC, NPC +/−, PC +/−, текущая ситуация). **Diminisher Value**: насколько один PC слабее партии, на которую рассчитан модуль (1/2, 1/3…), умножается число врагов или их HP/урон/ловушки. У нас уже есть Fellow, каталог монстров и масштабирование HP — вычисление «сколько врагов из 6 оставить» можно делать кнопкой на карточке схватки.

**B6. Тематические таблицы Meaning под SW2.5.** В книге 45 таблиц «Elements». Для нас важны (пишем свои слова): персонаж (внешность, характер, мотивация, происхождение, навыки, черты и изъяны, речи, имена-слоги), подземелье (описание, ловушки, пещеры, лес, местность, город, цивилизация, дом), существа (описание, умения, нежить, мутации), магия (эффекты заклинаний, магические предметы, проклятия, видения и сны, загадочное послание), мир (боги, легенды, знатный род, повороты сюжета, тон приключения, запахи, звуки). Каждая — d100 (или d20 для краткости), две ячейки на бросок. Особая — **Names**: слоги, которые *произносят*, а не читают, и «понятия» («число», «эмоция»), которые надо вставить словом. Применение: сидит в генераторах 6.6 (NPC, трактир, поселение, подземелье) как расширение, а не замена.

**B7. Поведение NPC.** Действие NPC — это вопрос судьбе («продолжает ли он то, что делал?»), а не бросок на таблицу каждый раунд. Да = ожидаемое/продолжает; Нет = следующее по вероятности; Исключительное Да = то же сильнее; Исключительное Нет = обратное или то же сильнее; событие = дополнительное действие. Для наших **монстров на столе**: кнопка «Что делает монстр?» — вопрос «продолжает ли?» с шансом «очень вероятно», плюс слова из таблицы «действия боя» при «Нет». Ещё интересно: **параметры NPC Fate-вопросом** — ожидаемое значение + (Да = как ожидали; Исключительное Да ≈ +25 %; Нет ≈ −25 %; Исключительное Нет ≈ −50 %; событие = особое условие). Пригодится, чтобы разнообразить монстров каталога (HP/урон ±) без ручной правки — аккуратно, ведь у карточек книжные значения.

## C. Возможно позже

- **C1. Fate Check 2d10**: сумма + модификатор от степени (−5…+5) и хаоса (−5…+5), ≥ 11 — «Да», 18–20 — исключительное «Да», 2–4 — исключительное «Нет», дубль с цифрой ≤ хаоса — событие. Быстрее таблицы; шанс исключительных выше.
- **C2. Несколько списков** (по регионам/PC): в сложных кампаниях обновлять только активный список. У нас — списки журнала по месту (гекс, подземелье, порт).
- **C3. «Не знаю» как чистка списков**: запись, на которой сработало «не знаю», вычёркивается — не надо решать о её актуальности заранее.
- **C4. Старт приключения.** Идея «первая сцена не проверяется хаосом»; стратегии открытия: своя идея, случайное событие, слова из Meaning, **4W** (кто / что / где / зачем — 4 броска по таблицам персонажей, действий, мест и действий) и засев списков тем, что придумано.
- **C5. Знание игрока и персонажа.** Стратегии: «проверь → спроси → тогда оно настоящее», «надёжная и ненадёжная информация», «иду с этим» (кинематографично), «лишнее знание как повод для проверки». У нас уже есть скрытие данных до Monster Knowledge; расширить можно скрытием ловушек (сделано) и слабых мест.
- **C6. Запись приключения**: журнал, блог, новелизация, «заметки → правка». У нас: экспорт журнала кампании в Markdown/печать.
- **C7. Стили игры**: симуляционный (много сюрпризов, сцены по «точкам интереса») и театральный (драма). Флаг в настройках — какие стратегии конца сцены предлагать (интерес / время или место / сдвиг сюжета / настроение / автоматический Interrupt).

## Что НЕ берём

- Длинные таблицы слов дословно (авторское право) — пишем свои на русском и английском.
- «Adventure Crafter» как отдельная система — нужен свой продукт; из него годится только мысль «Turning Point вместо Interrupt», но она требует его таблиц.
- Механику «Fate Questions заменяют все правила RPG»: Sword World 2.5 имеет полноценные правила, оракул остаётся для того, чего в книгах нет (A6).

## Что сделано (2026-10-11)

- **A1–A6** — фазы 6.7a/6.7b; **B1** — 6.7c; **B2, B5** — 6.7d (см. `roadmap.md`).
- **B3 вкус хаоса** — `OracleState.chaosFlavor` (полный / мягкий / без хаоса): шаг шанса «да» 5 / 3 / 0 п.п. на единицу хаоса, шаг шанса события 3 / 2, без хаоса событие фиксировано на 15 %.
- **B6 тематические таблицы** — пять тем (персонаж, место, существо, магия, мир) по двум спискам из 20 слов, RU и EN, свои слова (`solo.oracle.themes`); кнопка «Слова по теме». Таблицу имён (слоги) и остальные из 45 тем не брали.
- **B7 поведение монстра вопросом** — `lib/monster-action.ts`: «продолжает ли он?» с шансом «очень вероятно»; «нет» даёт одно из 12 новых действий, исключительные ответы усиливают, событие даёт лишнее действие. Кнопка «Что делает сейчас?» на карточке монстра. Параметры монстра вопросом (±25 %) не делали: у карточек книжные значения.
- **C1 Fate Check 2d10** — `askFate`: два d10 + модификатор степени (−5…+5) и хаоса (−4…+4, с учётом веса хаоса); «да» от 11, исключительное «да» от 18, исключительное «нет» при 4 и меньше; дубль с цифрой в пределах хаоса — событие. Переключатель «Отвечать: по таблице / два d10» (`OracleState.method`).
- **C2 списки по месту** — `CampaignEntry.place`, `Campaign.activePlace`: при заданном месте события берут записи этого места и «везде». Привязки к гекс-карте нет (место пишется руками).
- **C3 «не знаю»** — кнопка в строке события закрывает записи журнала, на которую оно указало (нить под Plot Armor не трогает); закрытого NPC можно вернуть в журнале.
- **C4 старт приключения** — «Начать приключение»: сцена 1 без проверки + четыре пары слов кто/что/где/зачем (темы персонаж, мир, место, персонаж).
- **C5 знание игрока и героя** — четыре подсказки в блоке «Как толковать ответы».
- **C7 стили игры** — `OracleState.style` (симуляция / драма): в форме «Закончить сцену» разные стратегии закрытия.
- **C6 запись приключения** — кнопка «Скачать журнал (.md)» в журнале кампании (`lib/campaign-export.ts`).

**Сознательно не взято:** B4 очки опасности (облегчают соло, при решении владельца можно добавить счётчик). Остальное из раздела C сделано.
