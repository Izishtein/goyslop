# Features

## Решено

| Вопрос | Решение |
|--------|---------|
| Аккаунты / облако | Нет |
| Хранение | localStorage (автосохранение) + ручной экспорт/импорт JSON |
| Локализация | en + ru, с возможностью добавить другие языки |
| Печатный вид | Кнопка «Печать / Сохранить в PDF» — `window.print()` + `src/print.css`. **Отклонение от изначального решения** (2026-08-12): react-to-print не генерирует PDF-файл, он открывает тот же системный диалог печати; настоящую генерацию даёт только `@react-pdf/renderer`, но ценой дублирующей вёрстки всего листа на своих примитивах. One-click скачивание `.pdf` — отдельная задача, требует подтверждения (см. открытые вопросы) |
| Калькуляция | Умная (Вариант А) — HP, MP, бонусы к броскам, инициатива считаются автоматически по формулам SW 2.5 |
| Dice roller | Вне MVP — отдельная фича после MVP |
| Список персонажей | Несколько персонажей в localStorage, нужен менеджер персонажей (список, создать/удалить/переключиться) |
| Версионирование JSON | Поле `schemaVersion` с первой версии |
| HP/MP трекер | В MVP. Current/max для HP и MP; current редактируется вручную (урон/лечение/трата MP), кнопка сброса к max при левелапе/отдыхе |
| Статус-эффекты | В MVP, структурированно. Активный эффект = имя + источник + длительность в раундах (или "permanent"/"until removed") + модификатор(ы) к конкретным полям (Accuracy/Evasion/Fortitude/Willpower/Defense/action checks и т.д.). Модификаторы автоматически учитываются в расчётных полях, длительность автоматически убывает по раундам/автоснимается на 0 |

## После MVP

### Опыт и уровни (2026-08-12)

Первая фича сверх MVP-чеклиста. До неё классы фиксировались в момент создания и не менялись, а XP предыстории показывался в списке и терялся.

- **Опыт — двухчисловой реестр** `experience: { total, spent }` в `CharacterSchema` (через `.default(...)`, старые сохранения добираются нулями). Ровно так его считают на бумаге: сколько получено и сколько уже превращено в уровни. Оба числа редактируются вручную — GM выдаёт опыт, и его можно потратить на то, чего приложение не моделирует.
- **Стартовый опыт берётся из предыстории**, а стартовые классы даются сверх него бесплатно (так в книге: у «Normal» без класса опыта больше — 3000 против 2000).
- **Секция «Классы и опыт»** на листе: `+1` / `-1` по уровню и добавление класса из каталога с учётом restricted classes расы. Стоимость уровня берётся из `lib/formulas/xp-cost.ts` (таблица Core II/III).
- **Правило симметрии:** всякое автоматическое изменение `spent` — точная обратная операция явной покупки (`+1` списывает полученный уровень, `-1` возвращает его же). **Удаление класса не возвращает ничего** — иначе удаление бесплатного стартового класса печатало бы опыт из воздуха. Расхождения правятся руками через поле «потрачено».
- Перерасход (`spent > total`) не блокируется, а подсвечивается красным остатком.

## Закрытые вопросы

### Версионирование JSON-схемы

- **При импорте старой версии — silent migration.** Новые поля добавляются в `CharacterSchema` через `.default(...)`, а каждое чтение из localStorage и каждый импорт проходят `CharacterSchema.safeParse` — недостающие поля добираются дефолтами молча, непарсящиеся персонажи отбрасываются с `console.warn`, не роняя список. Полноценный versioned-migration runner по `schemaVersion` понадобится только при ломающей смене формата (переименование/удаление полей), пока таких не было.

### Статус-эффекты — детали схемы

- **Список модифицируемых полей — фиксированный enum**: 6 характеристик + accuracy/evasion/fortitude/willpower/defense/actionCheck, плюс `custom` со свободным `customLabel` как запасной вариант.
- **У каждого эффекта свой независимый счётчик раундов** с момента наложения, не один общий на бой. Кнопка «Next round» тикает все сразу.
- **Пресетов нет — только ручной ввод.** Частые эффекты (яд, паралич, ошеломление) не заведены в данные.

## Открытые вопросы

- **One-click скачивание `.pdf`** — нужно ли оно вместо текущего диалога печати. Цена: `@react-pdf/renderer` с дублирующей вёрсткой листа, которая будет расходиться с реальной.
- **Dice roller** — по-прежнему вне MVP, как отдельная фича.
