# Features

## Решено

| Вопрос | Решение |
|--------|---------|
| Аккаунты / облако | Нет |
| Хранение | localStorage (автосохранение) + ручной экспорт/импорт JSON |
| Локализация | en + ru, с возможностью добавить другие языки |
| Печатный вид | Да, кнопка "Скачать PDF" (react-to-print / @react-pdf/renderer), не только CSS print |
| Калькуляция | Умная (Вариант А) — HP, MP, бонусы к броскам, инициатива считаются автоматически по формулам SW 2.5 |
| Dice roller | Вне MVP — отдельная фича после MVP |
| Список персонажей | Несколько персонажей в localStorage, нужен менеджер персонажей (список, создать/удалить/переключиться) |
| Версионирование JSON | Поле `schemaVersion` с первой версии |
| HP/MP трекер | В MVP. Current/max для HP и MP; current редактируется вручную (урон/лечение/трата MP), кнопка сброса к max при левелапе/отдыхе |
| Статус-эффекты | В MVP, структурированно. Активный эффект = имя + источник + длительность в раундах (или "permanent"/"until removed") + модификатор(ы) к конкретным полям (Accuracy/Evasion/Fortitude/Willpower/Defense/action checks и т.д.). Модификаторы автоматически учитываются в расчётных полях, длительность автоматически убывает по раундам/автоснимается на 0 |

## MVP (минимально рабочий продукт)

- [ ] Лист персонажа — все секции (см. [sheet-content.md](sheet-content.md))
- [ ] Автоматический расчёт производных значений (HP, MP, бонусы к броскам)
- [ ] Трекер current/max HP и MP
- [ ] Трекер статус-эффектов (длительность в раундах, авто-снятие, авто-применение модификаторов к расчётным полям)
- [ ] Автосохранение в localStorage
- [ ] Экспорт персонажа в JSON
- [ ] Импорт персонажа из JSON (с валидацией)
- [ ] Переключатель языка EN / RU
- [ ] Печатный вид (CSS print или PDF)
- [ ] Список персонажей (несколько в одном браузере)

## Открытые вопросы

### Версионирование JSON-схемы

- При импорте старой версии — silent migration или предупреждение?

### Статус-эффекты — детали схемы (для проектирования `character.ts`)

Решено, что трекер входит в MVP полноценно (см. таблицу выше). Остаётся уточнить при проектировании схемы:
- Список стандартных модифицируемых полей (Accuracy/Evasion/Fortitude/Willpower/Defense/action checks/конкретные характеристики) — фиксированный enum или свободное поле?
- Раунд считается один общий на сессию боя, или у каждого эффекта свой независимый счётчик с момента наложения?
- UI для быстрого наложения часто встречающихся эффектов (яд, паралич, ошеломление и т.д.) — пресеты или всегда ручной ввод?
