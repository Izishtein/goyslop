# Tech Stack

## Решено

| Вопрос | Решение |
|--------|---------|
| Платформа | React SPA |
| Бэкенд | Нет — только клиент |
| Аккаунты | Нет |
| Хранение | localStorage + экспорт/импорт JSON |
| Локализация | i18n, en + ru на старте, расширяемо |
| Сборщик | Vite |
| Стили | CSS Modules |
| UI-библиотека | Radix UI (headless-примитивы, стилизуются через CSS Modules) |
| Стейт | Jotai (атомарный подход для реактивности отдельных полей листа) |
| Валидация при импорте | Zod |
| JSON-схема | Версionирование с первого дня — поле `schemaVersion` |
| Печать | Кнопка "Скачать PDF" (react-to-print / @react-pdf/renderer) |
| Деплой | GitHub Pages из приватного репозитория. **Важно**: приватный GitHub Pages требует GitHub Pro/Team — иначе сайт станет публичным |
| Тестирование | **Vitest** (unit-тесты формул расчёта) + **Testing Library** (тесты компонентов) — полное покрытие |

## Тестирование

- **Vitest** — нативно интегрируется с Vite, без доп. конфигурации. Юнит-тесты для чистых функций расчёта (`src/lib/formulas/` или аналог): HP/MP, модификаторы характеристик, Adventurer Rank thresholds, Spell Slot Table, пороги Reputation и т.д. Тест-кейсы берутся из таблиц, уже задокументированных в `docs/sheet-content/` (значения там проверены по первоисточникам — экономит время на придумывание кейсов).
- **Testing Library** (`@testing-library/react`) — тесты ключевых интерактивных сценариев: ввод характеристик → пересчёт производных полей, наложение/снятие статус-эффекта → изменение расчётных полей, экспорт/импорт JSON с валидацией Zod, переключение персонажа в списке.
- Формулы и компоненты, покрытые тестами, разрабатываются как чистые функции/презентационные компоненты там, где возможно — упрощает и тестирование, и переиспользование.
